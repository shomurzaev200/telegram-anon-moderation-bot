# ANON v2 — Telegram-бот и админка

Полная новая реализация вместо заглушек. Ubuntu 22.04/24.04, Python 3.10+.
Русский интерфейс, порт 8080, Gunicorn, SQLite WAL и долговечная очередь задач.

## Установка

Сначала остановите старого бота и старую админку: Ctrl+C в их терминалах или
`sudo systemctl stop ИМЯ_СТАРОГО_СЕРВИСА`, если вы запускали через systemd.
Один токен нельзя использовать в двух одновременно работающих polling-процессах.
Старую папку не удаляйте. Этот проект хранит данные отдельно и НЕ переносит неизвестную старую схему.

```bash
cd ~
git clone --branch release-v2 --single-branch https://github.com/shomurzaev200/telegram-anon-moderation-bot.git telegram-anon-v2
cd telegram-anon-v2
bash install.sh
```

Установщик спросит токен от @BotFather и новый пароль (12+ символов).
При вводе секретов символы не отображаются — это нормально.
Пароля по умолчанию нет. Старый `ChangeMeNow!2026` не используется.
Запускайте установщик без sudo: он сам запросит sudo только для системных операций.
Сервисы автоматически запускаются после перезагрузки.

Откройте `http://IP_СЕРВЕРА:8080`. В «Настройки и чат» задайте:

- ADMIN_IDS — Telegram ID модераторов через запятую; команда `/id` у бота покажет ваш ID.
- MODERATION_CHANNEL_ID — отдельный закрытый канал модерации, ID `-100…`.
- PUBLIC_CHANNEL_ID — публичный канал публикаций, ID `-100…`.
- ANON_GROUP_ID больше не требуется и скрыт в панели. Старое значение остаётся в базе.
- CHAT_ENABLED — включить или выключить общий анонимный чат.
- CLEANUP_HOURS — 1–24, по умолчанию 12. COOLDOWN_SECONDS устарел: паузы для входящих сообщений нет.

Добавьте бота администратором двух каналов с правом публикации. Отдельная группа
не нужна: участники общаются в личных сообщениях с ботом.
Нажмите «Проверить Telegram» на главной; подробный результат появится в задачах.
Настройки применяются без перезапуска. Уже поставленные публикации сохраняют назначенный канал.

### Доступ к панели

Для прямого доступа разрешите входящий TCP 8080 в firewall/security group сервера
ТОЛЬКО со своего IP. Не вводите пароль по открытому HTTP через недоверенную сеть.
Можно не открывать 8080 наружу: создайте на Windows SSH-туннель (с теми же ключами,
что используете для обычного SSH):

```powershell
ssh -L 8080:127.0.0.1:8080 ubuntu@IP_СЕРВЕРА
```

Откройте `http://127.0.0.1:8080`. Для постоянного публичного доступа настройте HTTPS
через reverse proxy, измените bind Gunicorn на 127.0.0.1:8080 и поставьте
`"secure_cookie": true` в `data/secrets.json`, затем перезапустите админку.
Заголовки X-Forwarded-For намеренно не считаются доверенными: за proxy лимит
попыток входа будет общим для IP прокси, пока вы явно не настроите доверенную сеть.

## Что работает

- /start: меню, /post: приём одного сообщения на модерацию.
- Текст, фото, видео, анимации, документы, аудио и голосовые. Новые посты со стикерами/видеокружками не принимаются: у них нет подписи Анон.
- Копирование в канал модерации без ссылки на отправителя, кнопки публикации/отклонения.
- Проверка Telegram ID на каждое действие модератора; атомарная защита от двойного принятия.
- Веб-модерация с причиной отклонения и уведомлением автора.
- «Вступить в анонимный чат» (/chat): общая переписка через личку бота.
- «Выйти из анонимного чата» (/leave): прекращение доставки; повторный вход без истории.
- «Написать пост» (/post): только ОДНО следующее сообщение на модерацию. /cancel отменяет.
- Вне чата обычное сообщение не становится постом. После поста участник возвращается к чату.
- Текст до 3500 символов, фото/видео/анимации/документы/аудио/голосовые с подписью до 900.
- Получатели определяются на момент отправки; новые участники не получают старую очередь.
- Онлайн означает «вступил и ещё не вышел»: реальный статус online Telegram боту не сообщает.
- Псевдонимы на основе HMAC, смена вручную и после завершения очистки.
- Очистка только отслеживаемых сообщений этой версии бота, порциями до 500.
- Блокировка пользователей, лимит частоты, история, журнал, очередь, смена пароля.
- CSRF, хеширование пароля, ограничение попыток входа, завершение сессий при смене пароля.
- Вход/выход и сохранение настроек не вызывают Telegram API.
- База создаётся независимо от порядка запуска процессов; путь не зависит от текущей папки.

Медиа в веб-панели представлены подписью/типом; просмотр оригинала — в закрытом
канале модерации. Альбомы не объединяются: бот просит отправлять медиа по одному.
Личные контакты, локации, опросы и служебные сообщения не принимаются как посты.
В чате нет альбомов, стикеров, видеокружков, контактов и локаций. Это общий чат, не случайные пары.
Внешних CDN, платных API и ИИ-сервисов нет.

## Надёжность и ограничения

При явном отказе Telegram задача помечается failed. При таймауте/обрыве сети
результат может быть неизвестен: статус uncertain, без автоматической повторной
публикации. Перезапуск также помечает незавершённые задачи uncertain. Проверьте
канал вручную прежде чем создавать новую заявку. Telegram не предоставляет
идемпотентный ключ для copyMessage: абсолютная гарантия «ровно один раз» невозможна.
При HTTP 429 очередь ждёт retry_after; другие задачи продолжают выполняться.

Удаление может быть запрещено правами или ограничениями Telegram. Счётчики успехов
и неудач видны в задачах. Сообщения со статусом удаления failed не повторяются
автоматически. Очистка отслеживает исходные сообщения участников в личке и доставленные ботом копии;
включая команды, отправленные посты, приветствия и ответы бота. Заявки в базе и
посты в каналах сохраняются. Сообщения в старой группе не удаляются.
Сообщение, отправка которого уже началась одновременно с выходом, ещё может прийти.
Ответы через кнопку Telegram «Ответить» связываются с локальной копией исходной реплики
у каждого участника. Если участник не видел оригинал, старый текст ему не раскрывается.
Heartbeat показывает жизнь процесса, а доступность Telegram проверяется отдельно.
Восемь сетевых workers работают параллельно. Один получатель обслуживается последовательно;
это решение не обещает тысяч отправок в секунду. Telegram ограничивает доставку.
Журнал/очередь сохраняются без автоматического удаления: следите за размером data/.

Анонимность — для аудитории: в базе хранятся Telegram ID, исходные тексты, сведения
о заявках и задачах. Администратор сервера имеет к ним доступ. Не обещайте пользователям
полную неотслеживаемость; сам контент может раскрывать автора.

## Управление

```bash
sudo systemctl status anon-v2-bot anon-v2-admin --no-pager
sudo journalctl -u anon-v2-bot -n 100 --no-pager
sudo journalctl -u anon-v2-admin -n 100 --no-pager
sudo systemctl restart anon-v2-bot anon-v2-admin
```

Ручной запуск после настройки (не одновременно с systemd):

```bash
source venv/bin/activate
python bot.py
# другой терминал, та же папка и venv:
python admin.py
```

Сброс забытого пароля: `venv/bin/python setup.py`, Enter для сохранения токена,
задайте новый пароль. Все старые веб-сессии станут недействительны.

Обновление:

```bash
cd ~/telegram-anon-v2
sudo systemctl stop anon-v2-bot anon-v2-admin
cp -a data "data-backup-$(date +%Y%m%d-%H%M%S)"
git pull --ff-only
venv/bin/pip install -r requirements.txt
sudo systemctl start anon-v2-bot anon-v2-admin
```

Не копируйте старую базу поверх `data/anon-v2.sqlite3`: нужен отдельный перенос после
анализа реальной схемы. При откате остановите v2 и запустите старые сервисы.
Токен лежит только в `data/secrets.json` (600), каталог data исключён из Git.

## Проверки

```bash
venv/bin/pip install pytest==8.4.2
venv/bin/python -m pytest -q
```

Тесты используют временную базу и имитацию Telegram API, ничего не отправляют.
Реальная доставка требует вашего токена и корректных прав в каналах.
Документация: https://core.telegram.org/bots/api и https://flask.palletsprojects.com/en/stable/deploying/gunicorn/


## Обновление общего чата

Обновляйтесь стандартной командой выше с остановкой обоих сервисов и копией data/.
Миграция сохраняет настройки, пароль, заявки и историю постов. Старые режимы ввода
сбрасываются: каждый пользователь должен заново нажать /start и «Вступить».
Старые ожидающие задачи доставки в группу отменяются. Уже созданные заявки на
модерацию не удаляются: ошибочные старые заявки отклоните вручную.

Предупреждение об удалении всей личной переписки показывается при /start и входе в чат. Очистка выполняется с заданным
интервалом, а не строго через 12 часов после каждого сообщения. Нельзя гарантировать
удаление скриншотов/копий или недоступных для удаления сообщений Telegram.
Исходное содержимое завершённых доставок чата удаляется из payload очереди; это
не криптографическое стирание SQLite/WAL/резервных копий и не полная анонимность
от администратора сервера. Не публикуйте data/.

Новые посты сохраняют текст или Telegram file_id отдельно от исходного сообщения: удаление
личной переписки не ломает их модерацию/публикацию. Переписку до этого обновления,
которую бот не отслеживал, задним числом автоматически удалить нельзя.


## Ответы, реакции и общение

- Используйте обычную функцию Telegram «Ответить» (свайп по сообщению на телефоне).
  Ответ увидят все текущие участники; у автора он привязан к его исходному сообщению,
  у остальных — к их собственной копии. В тексте дополнительно указан анонимный адресат.
- Связи ответов работают для сообщений, отправленных после установки этого обновления.
  Сообщения до обновления не имеют таблицы соответствий и цитатами не связываются.
- Новому участнику не показывается содержание старой реплики, даже если кто-то на неё отвечает.
  После выхода/повторного входа старые ссылки нельзя использовать для цитирования.
- Под доставленными сообщениями — кнопки 👍 ❤️ 😂 🔥. Это общие анонимные реакции
  нашего бота, не встроенные Telegram-реакции. Одна реакция на человека: повторное
  нажатие убирает её, другая кнопка заменяет. Счётчики обновляются у получателей;
  автору приходит уведомление со счётчиками в ответ на его оригинал.
- При вступлении появляются кнопки «Кто в чате» и «Тема для разговора».
  Также доступны /members и /topic. Список показывает только псевдонимы (до 50),
  количество вступивших и пометку «ты». Telegram online-статус не отслеживается.
  Тема показывается лично: пользователь сам решает, что написать остальным.
- Две основные кнопки меню сохранены. Реакции и дополнительные функции доступны
  только вступившим участникам. Нажатия дополнительных кнопок ограничены раз в 2 секунды.
- Очистка удаляет цитаты, связи копий и реакции на очищенные сообщения. Записи
  участников и заявок на модерацию сохраняются. В SQLite/бэкапах это не secure erase.


## Аноны, комментарии и очередь доставки

После одобрения текст/подпись заканчиваются на «Анон.». Кнопка канала
«Анонимные комментарии» открывает бота через deep link. Это НЕ встроенная ветка
Telegram-комментариев: отдельная discussion group не нужна, аккаунты авторов
не публикуются. При запуске бот получает свой username через getMe.

Все пользователи, ранее начавшие диалог с ботом и не отключившие уведомления,
получают уведомление о новом опубликованном аноне. /notifications включает и
выключает уведомления. Бот не может написать подписчику канала, который никогда
не запускал бота. Уведомления отправляются только после успешной публикации.

В обсуждении есть кнопки чтения, написания и перелистывания. Комментарий — текст
до 800 UTF-16 единиц, без предварительной модерации. Он не попадает в общий чат.
Каждый видит псевдонимы авторов и может прочитать все нескрытые комментарии.
В админке раздел «Комментарии» позволяет скрывать/возвращать комментарии.
Скрытие действует на новые просмотры; уже доставленные копии удаляются при очистке.
Комментарии хранятся вместе с постами, несмотря на очистку личной переписки.

Лимит нового поста: 4089 UTF-16 единиц текста или 1017 подписи, чтобы осталось
место для Анон. Старые слишком длинные посты получают явную ошибку публикации,
их нужно сократить и отправить заново; автоматического обрезания нет.

Входящие сообщения принимаются без 10-секундного ограничения. Для исходящих
запросов действует общий ограничитель: максимум 25 записывающих запросов/с,
не чаще 1 запроса/1.05 с в одну личку и 1/3.05 с в канал. При 429 соблюдается
retry_after. Платные рассылки НЕ включаются. Это сознательно консервативные значения.
Ожидание слота не блокирует worker: задача откладывается в SQLite, а worker берёт
задачу другого получателя. Порядок очереди каждого получателя сохраняется.
Глобальный порядок доставки разным людям не гарантируется.

При 60 участниках 60 сообщений общего чата создают 60×59=3540 доставок. При лимите
25/с это минимум около 142 секунд даже без сетевой задержки. Очередь позволяет
принять всплеск, но не делает массовую рассылку мгновенной. Публикации, кнопки и
ответы получают приоритет между очередями получателей. На главной админки видны
размер очереди, выполняемые задачи и возраст самой старой задачи.

Синтетический тест: 60 одновременных отправителей → 3540 успешных доставок через
8 workers без дублей/ошибок. Telegram заменён имитацией; этот тест проверяет
хранение, конкуренцию и порядок, не реальные лимиты API и не мощность вашего сервера.
Не меняйте SQLite на Redis/PostgreSQL просто ради 60 пользователей: сначала следите
за размером очереди, ошибками, RAM/CPU и задержкой диска. Для устойчиво высокой нагрузки
понадобится отдельное планирование распределённой очереди и хранилища.
